# v0.3.1 设计计划：真机计时卡片与农场布局修复

日期：2026-11-04。状态：代码修改与模拟器验收完成，待 vivo X300 真机确认。
代码基线：v0.3.0，`versionCode = 6`；计划发布 v0.3.1，`versionCode = 7`。
本分支已更新到 v0.3.1 元数据；尚未发布 APK 或写入真机验收结论。

## 1. 目标与已知事实

本次为 UI 修复版本，优先解决 vivo X300（用户提供的 6.31 英寸设备）上的两个问题：

1. 计时页面仍显示宽大的单列卡片，信息密度低，开始按钮占据整行。
2. 农场页面的信息层级、田地布局与说明卡排版不协调。

依据为用户提供的两张真机截图，以及用户补充的“ADB 模拟器测试时是双列”。
因此，**模拟器双列只是一个已通过的场景，不能据此认定真机适配完成**。

| 已确认 | 待采集，不作事实假设 |
| --- | --- |
| 真机截图原始分辨率为 1216 × 2640 | 真机有效 density、显示大小、字体大小、应用可用 dp 宽度 |
| 真机截图中计时卡片为单列，模拟器测试为双列 | 模拟器和手机是否安装相同构建、相同包名与版本 |
| 仓库当前使用自适应列数，Compact 卡片最小宽度为 156dp | 真机具体触发单列的配置，以及是否有额外窗口宽度约束 |
| 农场说明正文被右侧归档摘要挤窄 | 真机深色主题、大字体和不同系统显示大小下的表现 |

设备对角线和像素分辨率不作为布局断点；布局按组件实际获得的宽度决定。
沿用项目现有雾蓝配色、白卡片和农场插画，重点改变结构和信息分配。

## 2. 问题定位

### 2.1 计时：存在明确的双列宽度门槛

相关代码：

- `feature/tracker/src/main/java/com/meolist/feature/tracker/TrackerScreen.kt`：
  `GridCells.Adaptive(minSize = minimumCardWidth)`，左右各 16dp 页边距。
- `core/src/main/java/com/meolist/core/theme/MeoLayout.kt`：
  Compact 的 `trackerCardMinWidth = 156dp`、`trackerGap = 6dp`。
- `core/src/main/java/com/meolist/core/theme/Theme.kt`：小于 600dp 使用 Compact。

在当前 Compact 参数下，容器至少需要：

```text
2 × 156 + 6 + 2 × 16 = 350dp
```

才能容纳两列。405dp 的模拟器可以显示双列；低于 350dp 的容器会切为单列。
例如，同为 1216px 宽，若有效 density 为 560dpi，换算宽度约为 347.4dp，
便可能落到单列。这只是可复现的假设场景，**不是对手机当前 density 的测量结果**。

还存在独立的降级问题：当前单列仍复用纵向网格卡片，保留头部、时长、副标题和
全宽按钮，即使列数降级合理，卡片也会显得过大。只减小 156dp 或强制两列不能完整解决。

### 2.2 农场：说明卡和田地布局存在结构问题

`feature/farm/src/main/java/com/meolist/feature/farm/FarmScreen.kt` 中：

- `FarmInfoCard` 在一个 `Row` 中依次放图标、`weight(1f)` 正文和无宽度限制的归档摘要。
  摘要优先占据横向空间，正文被压成很窄的一列；截图与这一机制一致。
- `FarmScene` 固定 `chunked(3)`，最后一行用加权 `Spacer` 补齐。
  五块田时形成 3 + 2，右下角留下空位；大字体下三列田地也偏窄。
- 指标胶囊由 `FlowRow` 自然换行，专注时长较长时形成不均衡的两行。
- 田地里的名称、阶段和数值有单行限制，作物名称还使用省略号；需要纳入大字体修复。

## 3. 计时页面设计

### 3.1 正常状态：优先紧凑双列

以实际内容宽度为输入选择两列。短名称、普通时长在 360dp 和 405dp、1.0x 字体下
应为双列；补充约 347dp 场景用于复现现有门槛。1.3x 字体以实测可读性决定是否保留双列。

```text
计时                         记录  更多

┌────────────────┐  ┌────────────────┐
│ 图标 网课   ⋮  │  │ 图标 毕业设计 ⋮│
│ 今日 15分钟    │  │ 今日 0分钟     │
│                │  │                │
│    ▶ 开始      │  │    ▶ 开始      │
└────────────────┘  └────────────────┘
┌────────────────┐  ┌────────────────┐
│ 图标 做题   ⋮  │  │ 图标 阅读   ⋮  │
│ 今日 28分钟    │  │ 00:24:18       │
│                │  │ 今日累计 42分钟│
│    ▶ 开始      │  │    ■ 停止      │
└────────────────┘  └────────────────┘
```

示意表达信息顺序，不代表已完成渲染；实际卡片采用相同的状态空间预算。

- 图标、名称和更多菜单组成紧凑头部；较长名称可换行，菜单点击区域保持至少 48dp。
- 时长为视觉主体，使用现有等宽数字样式；“今日”标签与统计值紧邻，减少空白。
- 开始与停止使用一致的 48dp 最小触控高度，颜色和图标区分状态。
- 普通、无目标、短名称卡片在 1.0x 下以约 144–164dp 高为原型目标；不是固定高度或裁切上限。
- 有目标的卡片保留目标进度与说明；关联任务或备注自然换行，空间不足时进入横向卡片布局。
- 长累计时长、跨百小时运行时长以测量与可换行排版处理，不用极端时长样本决定所有卡片的列数。
- 多个运行计时器沿用简洁的运行数量与“全部停止”摘要条，不重复展开各卡片内容。

### 3.2 窄屏或大字体：紧凑横向单列

无法在双列下完整显示必要文字和操作时，整组卡片切换为横向布局：

```text
┌─────────────────────────────────────┐
│ 图标  网课                  ▶ 开始 ⋮│
│       今日累计 15分钟               │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ 图标  阅读                  ■ 停止 ⋮│
│       00:24:18 · 今日累计 42分钟     │
└─────────────────────────────────────┘
```

- 普通短内容以约 88–112dp 高为原型目标；长文本和目标信息可自然增高。
- 操作区使用内容宽度，不再是横跨整张大卡的独立按钮。
- 更窄或更大字体时，操作区可以换到下一行，避免挤压名称与时长。
- 不能为了保住双列而缩小字号、减少触控区域或截断文字。

### 3.3 实现边界

- 从网格容器约束扣除页边距、列间距，结合文字测量选择布局；不按机型或屏幕英寸分支。
- 提取可单元测试的布局决策，输入可用宽度与测量后的必要内容尺寸。
- `fontScale` 只通过文字测量影响换行和布局选择，不乘到 padding、卡片最小宽度或触控尺寸上。
- 布局选择与是否运行无关；对已知的静止/运行内容取所需空间的较大值，目标信息同样参与测量。
  相同内容配置下，开始、运行中和停止后的卡片高度一致。
- 不使用 `animateContentSize`、按运行状态改变 padding，或在开始时切换列数。
- 新增卡片尺寸、操作区和间距指标集中到 `MeoLayout`，同时提供 Compact 和常规值。
- 最后一行需能滚动到悬浮新增按钮和底部导航上方，所有操作均可点击。

## 4. 农场页面设计

### 4.1 信息顺序

```text
计时农场                            成就

┌─────────────────────────────────────┐
│ 收获 5 次         连续 4 天         │
│ 专注 15小时12分钟                   │
│                                     │
│    自适应田地：作物图、名称、阶段     │
│    进度条、养分数值、成熟状态         │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 图标  每块田都会生长                 │
│ 每块已解锁的田地都会获得养分，        │
│ 并独立储存剩余养分。                │
│ ─────────────────────────────────── │
│ 旧农场已归档 · 6块田 · 收获3次      │
└─────────────────────────────────────┘

成就                            全部成就
```

指标采用“收获 / 连续”双项区和单独一行的专注时长，避免长时长胶囊挤压其他指标。
大字体或英文较长时允许顺序堆叠。背景太阳与山丘保留为低对比装饰，不与文字竞争。

### 4.2 田地排列

| 容器与内容条件 | 排列策略 |
| --- | --- |
| 三列能完整显示作物名、阶段和养分值 | 五个槽位使用 3 + 2；第二行两张卡平分整行 |
| 三列不足、两列可读 | 2 + 2，最后一张为占满整行的紧凑横向田地卡 |
| 更窄容器或更大文字导致两列仍不足 | 单列横向田地卡 |

- 使用局部内容测量决定列数；405dp / 1.3x 和真机实际配置是必测场景。
- 不用空 `Spacer` 保留一个不存在的第六块田；所有行用满卡片内容宽度。
- 同一行的田地卡等高；作物图尺寸按布局令牌控制，不因字体比例放大。
- 已种植：作物图 → 名称 → 阶段 → 进度条 → 完整养分值；名称、阶段、数值可换行。
- 成熟：保持同样结构，以成熟颜色和“可收获”状态突出，点击进入现有收获交互。
- 空地：显示种植入口，存在余额时完整显示储存养分。
- 锁定：锁图标与解锁条件保持清晰，复用现有点击提示；不与成熟状态混淆。
- 成就和收获历史仍在场景之后。允许大字体增加页面高度，不以强塞进一屏为验收目标。

### 4.3 说明卡修复优先级最高

将 `FarmInfoCard` 改为纵向结构：

1. 首行放小图标和标题。
2. 正文占整张卡片内容宽度，自然换行。
3. 仅存在旧农场归档时，底部分隔区显示归档摘要，允许换行。

归档信息不能继续与正文争夺横向空间。已有字段和数据足以完成本次修复，
不增加归档详情页、弹窗或新的持久化开关。

## 6. 验收方案

### 6.1 先记录真机与模拟器的差异

分别用设备序列号执行，避免默认连到模拟器：

```text
adb devices -l
adb -s <serial> shell wm size
adb -s <serial> shell wm density
adb -s <serial> shell settings get system font_scale
adb -s <serial> shell dumpsys package <package>
```

`<package>` 分别核对 `com.meolist.app` 和 `com.meolist.app.debug` 的实际安装情况。
记录 `versionName`、`versionCode`、截图对应的包和构建来源；开发记录同时注明 commit。
调试构建额外记录应用的 `screenWidthDp`、density、fontScale 和内容容器宽度。
采集过程不打印用户任务、备注或其他个人数据。

真机先按用户当前配置验收，不先改变手机显示大小或字体来“修好”截图。
若暂不能连接真机，明确标为待验收；模拟器结果不能替代真机通过。

### 6.2 布局与交互矩阵

| 维度 | 覆盖要求 |
| --- | --- |
| 设备 | vivo X300 当前配置；模拟器 1216 × 2640 / 480dpi；补充 560dpi 假设场景 |
| 逻辑宽度 | 320、约 347、350 门槛上下、360、405、至少 600dp；窗口缩放后重新计算 |
| 视觉组合 | 中英文 × 浅深主题 × 1.0x / 1.3x 字体；真机额外保留用户原配置 |
| 计时内容 | 截图中的短名称、长中文名、长英文名、零记录、长累计、跨百小时、目标、任务、备注 |
| 计时状态 | 0 / 1 / 多个运行；开始、停止、调整、放弃、归档及全部停止 |
| 农场状态 | 3 / 4 / 5 解锁；5 个槽位均呈现；空地、种植、成熟、锁定、长养分值 |
| 农场说明 | 有/无旧农场归档；长中英文摘要；无归档时不留空分隔区 |

- 计时短内容在 360dp / 405dp、1.0x 下保持双列；约 347dp 验证优化后的双列可读性，
  若实测放不下则必须进入紧凑横向布局，不能回到截图中的高大单列卡片。
- 真机的主要验收标准是更紧凑、文字完整、操作可达；不将“永远双列”作为硬性指标。
- 通过 `uiautomator dump` 记录计时卡片的开始前、运行中、停止后 bounds，比较相同内容配置的高度。
  同时记录布局模式、完整可见卡片数，与原始基线比较；未测量前不宣称缩小百分比。
- 农场正文不再成为狭长文字列；归档文字不抢宽度；每行田地占满内容宽度。
- 两页无重叠、无被截断或省略的必要文字；新增按钮、底栏和系统导航不遮挡最后一项操作。
- 点击坐标来自 UI bounds，不从缩放后的截图推算。
- 截图与 bounds 保存在 `build/screens/small` 的 v0.3.1 验收子目录。
  模拟器试验后恢复显示/字体覆盖；真机不擅自更改用户设置。

### 6.3 自动验证与数据回归

- 布局决策提取成纯函数，测试宽度临界值、字体测量输入变化、长内容和尾行填满策略。
- 扩充 `MeoLayoutTest`，验证 Compact/常规令牌，避免已有页面被全局尺寸调整影响。
- 执行 `./gradlew test`、`./gradlew assembleDebug`、`./gradlew lintDebug`；
  有模拟器时执行 `./gradlew connectedDebugAndroidTest`。
- 冒烟检查计时结算、通知、农场种植/收获、页面切换与备份恢复；
  确认既有记录、田地余额、解锁进度、归档数据和运行计时器不被 UI 调整重置。

## 7. 发布边界

本次不改变养分规则、作物需求、解锁门槛、计时结算和历史记录。
维持 Room v2、备份格式 2 与格式 1 导入兼容，不引入数据库迁移或新依赖。

验收完成且进入发布工作时，再同步修改：

- `app/build.gradle.kts`：`versionName = "0.3.1"`、`versionCode = 7`。
- 设置页中英文 `settings_app_version`。
- 必要的双语 README 和发布说明，说明 UI 修复、数据兼容、无新增迁移。

发布前按仓库既有流程验证签名与 APK 信息；未完成真机验收，不把“vivo X300 已修复”写入发布结论。

## 8. 实施结果

- 计时页使用内容宽度计算列数。Compact 容器在约 315dp 内容宽度保持双列；320dp 窗口降级为
  横向紧凑单列。开始/停止控件保持 48dp 最小触控高度。
- 计时时长同时保留空闲与运行状态的文字布局，解决中文字符和非等宽数字字体度量不同导致的
  状态切换高度变化。
- 农场指标改为收获/连续双项和独立专注行；五块田按可用宽度重排。两列布局的末项使用横向
  田地卡，同一行田地卡等高。
- 农场说明卡改为纵向结构，归档摘要位于分隔线之后，不再挤压正文。作物、阶段、养分和锁定
  条件均取消单行省略。
- 响应式列数与田块宽度决策已加入 `MeoLayoutTest`。

模拟器验收使用 1216 × 2640 / 480dpi，覆盖：

| 场景 | 结果 |
| --- | --- |
| 405dp、中文、1.3x、浅色 | 计时双列；农场 3 + 2；说明卡正文完整 |
| 405dp、中文、1.0x、深色 | 计时双列；农场 3 + 2；颜色与文字可读 |
| 347dp、中文、1.3x、浅色 | 计时双列；农场 2 + 2 + 1 横向田块 |
| 347dp、英文、1.3x、浅色 | 计时双列；农场文字与归档摘要完整换行 |
| 320dp、中文、1.3x、浅色 | 计时横向紧凑单列；农场 2 + 2 + 1 横向田块 |
| 405dp、开始/运行 | 开始与停止按钮纵向位置一致，卡片等高 |

验收截图和 UI 层级保存在 `build/screens/small/v031-*`。模拟器显示尺寸、字体和语言已恢复。
vivo X300 的原始显示配置仍需连接设备后按第 6.1 节记录并复测。
